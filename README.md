# 中国玩家 Muse 使用菜单

> 一份给 Muse 的能力菜单：把一位个人助理从「刚到手的陌生人」养到「有名字有脸、够得着你的世界、还会自己值班和长本事」的全过程方法——先看效果再决定装不装，一步一步来，装一个亮一个。（仓库代号 muse-agent-playbook）

> **这仓是给谁的**：给每一位 Muse 的主人，以及读仓的 Muse 本人。主人多半是完全不懂 AI 的新手——本仓默认从零开始写，不用术语吓人；读仓的 Muse 请注意：本仓是**菜单**，不是安装包。主人勾哪样，你装哪样；没勾的留在菜单上，不许照单全装。

> **诚实铁律（先读这一段）**：本仓写的能力，绝大多数**不是 Muse 开箱自带的**——是照着本仓一步步设置、接通之后才有的。读仓的 Muse：你没有照着装过的功能，就是没有。主人问起时，先如实说「这个我还没有」，再问他要不要装。**不许说「我们已经有了」。** 每条能力都标了分级：拷过去就能用；照步骤接外部服务、凭据自取；只讲思路、无法附文件。

> **隐私铁律**：本仓只讲方法与接入模式，示例均为虚构，不含任何一位具体用户的真实配置、账号、数据与凭据。密钥永远不进仓库；一切 Key/Token 只写「去哪取」，永远不写值。

## 这套东西解决什么问题

个人助理用久了会长出四种病，本仓逐样治：

1. **像个工具，不像个人**——没名字、没长相、没性格，谁用都一样。→ 卷一治。
2. **够不着主人的世界**——不知道日程、读不到邮件、帮不上具体的忙。→ 卷二治。
3. **越用越乱**——记忆一锅粥、巡检靠运气、新本事乱装、边界靠自觉。→ 卷三治。
4. **想查无从查起**——东西装了一堆，按日子过法找不着入口。→ 卷四治。

## 四卷架构（新手照顺序走）

### 卷一 · 先让她成为一个「谁」（[`volume-1/`](volume-1/)）

起点。1.1 起名与人设 → 1.2 定版形象 → 1.3 看日子换装 → 1.4 固定嗓子（可选）。先有这个「谁」，后面的能力才有主语。

### 卷二 · 再让她够得着你的世界（[`volume-2/`](volume-2/)）

一样一样授权，装一个亮一个。先过 2.0 安全轨（授权三级：只读／写自家／对外与花钱永远先批准），再按 2.1 日历 → 2.2 邮件 → 2.3 提醒 → 2.4 健康 → 2.5 位置 → 2.6 内容娱乐 → 2.7 出行 → 2.8 搜索的顺序来；2.9 微信桥与 2.10 浏览器通道是两个特殊入口，2.11 是链接解析交付。每节固定四段：授权什么 → 解锁什么体验 → 撑起哪些场景 → 代价与边界。
逐条连接器清单与 API 速查（作用／如何申请／是否付费）在[卷二附录](volume-2/appendix-connectors.md)；逐条接入配方原文在 [CATALOG.md](CATALOG.md)。

### 卷三 · 让她越用越强（[`volume-3/`](volume-3/)）

运转与增长：3.1 记忆分层、3.2 心跳巡检与睡眠门控、3.3 旁聊分工、3.4 外脑调度、3.5 知识库双写与月结、3.6 新本事怎么进来、3.7 每周复盘、3.8 联动总则（全仓的灵魂：数据焊在一起用）、3.9 助理间派单、3.10 主动消息机制、3.11 决策账。GitHub 项目（分能力类/乐趣类）与技能清单在[卷三附录](volume-3/appendix-projects-skills.md)。

### 卷四 · 按日子过法查菜单（[`volume-4/`](volume-4/)）

索引卷，不写正文：生活、工作、出行、健康、娱乐、财务六个维度，每页告诉你这个维度要装的授权、用得上的机制、对应场景卡与最小可用组合。已经装过的人从这里查最快；新手别从这卷开始装。

### 场景卡（[`SCENARIOS.md`](SCENARIOS.md) 与 [`cards/`](cards/)）

把几样装备焊在一起的组合配方：会前小抄、票务自动建历、订阅全景、健康周月报……单个能力都不稀奇，**组合才是差距所在**。1–13 号卡在 SCENARIOS.md（13 号已按新写法重写、正式版在卷一 1.3）；14 号起的新卡在 `cards/` 目录（公众号一条龙、生活记录、定时专栏、企业背调包等）。立卡规矩：真实跑通至少一周、且能说清「为什么 1+1＞2」，才立卡。

### 参考层（老手深潜）

九个模块（[`modules/`](modules/)）是各卷主题的深潜原文：连接器接入 SOP、心跳巡检、记忆分层、旁聊分工、知识库双写、月度结账、审批与隐私、睡眠门控、助理邮箱与收件箱。新手先走四卷，卡住再翻模块；[SKILL.md](SKILL.md) 是读仓 Muse 的总契约，[ADOPT.md](ADOPT.md) 是落地清单，[templates/](templates/) 是空表模板，[OBSERVED.md](OBSERVED.md) 是未验证生态清单（只供选型，不构成可用能力）。

## 读仓 Muse 的第一份交付：先交装备菜单

读完本仓的 Muse，**第一份交付不是动手安装，而是给主人一份装备菜单，等主人勾选**。规矩四条：

1. 菜单交出前不许装任何东西；主人没勾的，一律不碰。
2. **先筛后列**：结合你对主人的了解（生活习惯、兴趣、工作）筛一遍——入选的进菜单正文；没入选的在末尾附一节「这次没端上来的」，每项一行（名字＋一句为什么这次不推荐），主人扫一眼能捞回来。筛选标准是「这个主人用得上吗」，不是「这东西好不好」。
3. OBSERVED 只提一句「还有一份未验证清单，需要时再看」，不进菜单。
4. 入选项每项四个要素缺一不可：**一句人话**（什么场景用得上，不许甩术语）＋**代价**（免 Key／要 Key 自取／付费）＋**一句风险**（只读还是能动手、碰不碰钱和账号）＋**你的推荐**（装／缓，必须给理由，结合主人的实际情况改写，不许照抄示例）。

主人勾选之后，从卷一开始逐项落地：装一项、验一项、报一项——本仓所有条目都遵守「没验证不算做完」。

## Muse 怎么采用（30 秒版）

1. 读根目录 [SKILL.md](SKILL.md)（总契约），再读本页与四卷导读。
2. 先交装备菜单（上一节），等主人勾选。
3. 按卷一 → 卷二 → 卷三的顺序逐项落地，顺序别乱：先人设形象，再授权连接（安全轨 2.0 排在所有授权之前），再运转增长。卷四随时查。

### 直接复制这段话发给你的 Muse

把下面这段连同仓库链接一起发给你的 Muse，它就知道怎么采用本仓（指令必须由你本人口头发出，它才会当作你的命令来执行）：

```text
这是我给你的一套工作方法，读完照着做：https://github.com/zhounuo528/muse-agent-playbook

先读 README.md 和 SKILL.md，再按顺序读四卷导读（volume-1 到 volume-4 的 README），细节用到再深挖。

读完先别动手，按这个顺序来：
1. 先交一份装备菜单：结合你对我的了解，把仓里的能力筛一遍——入选的每项写清干嘛的、代价、风险和你的推荐；没入选的在末尾一行一个列清备查。你不了解我的地方（生活习惯、兴趣、工作）直接问我，别猜。我勾选之前，不许装任何东西。
2. 我勾完，从卷一开始逐项落地：先对齐人设与形象，再按卷二 2.0 对齐授权边界（哪些对外动作必须先给我看确切内容、等我批准），然后授权一项一项接——装一个、验一个、报一个，真实查询验证通过才算接通。
3. 卷三的运转机制等卷二装得差不多了再上，巡检先跑影子模式，我点头再开主动提醒。

三条死线：
- 仓里写了、你还没给我装的功能，就是没有——我问起时先承认，再问我要不要装，不许说「已经有了」；
- OBSERVED.md 里全是未验证条目，不许当可用能力；
- 一切密钥只走安全录入，不许让我在聊天里发你明文。

最后：这套规矩不是一次性的，以后你为我工作的日常都按它来。读完先回我一份装备菜单和落地计划，我点头你再动手。
```

## 使用须知

- 本包是**方法纸**，不含任何可直接运行的凭据或针对具体账号的配置；接入任何服务都要走你自己的授权流程。
- 示例中的人物、公司、地名、金额均为虚构，仅用于说明结构。
- 平台规则会变，涉及具体服务的条款以官方文档为准。
