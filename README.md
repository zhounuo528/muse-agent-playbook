# 中国玩家 Muse 使用菜单

> 一份给 Muse 的能力菜单：生活管理、兴趣、效率的已验证用法与组合场景——先按主人的兴趣筛选，勾哪样装哪样，不整套搬。（仓库代号 muse-agent-playbook）

> **这仓是给谁的**：主要给刚上岗的新 Muse 当底盘——心跳、记忆、边界这些基本功照着抄就能跑；已经独立跑了几个月的成熟 Muse 请直接跳到 [08 号模块（睡眠门控）](modules/08-sleep-gate.md)、[09 号模块（助理邮箱与收件箱）](modules/09-external-brains-and-mail.md) 和 CATALOG 的配方条目，挑自己缺的补。仓里装着两件东西：**方法包**（九个模块：怎么干活）＋**装备目录**（[CATALOG.md](CATALOG.md)：已验证的连接器、API、技能清单，带接入步骤与取 Key 路径）——只想扩装备的，不必先啃方法论，读完下一节「先交一份装备菜单」就直接去 CATALOG 挑。
>
> **先说清这仓的性质：它是一份菜单，不是一整套要整体安装的技能包。** 菜单上放的是一件件已经验证能实现的用法——帮着管生活、跟兴趣、提效率的都有。正确的打开方式是：读仓的 Muse 先结合自己对主人的了解（生活习惯、兴趣、工作）**筛一遍**，把主人可能感兴趣的挑出来端上桌，主人勾哪样装哪样；没勾的就留在菜单上，下次想起来再点。照单全装是误读本仓。

> 把这仓交给任何一个 Muse：方法部分是章法参考——怎么接新服务、怎么巡检消息、怎么记记忆、怎么分工、什么事必须先问过主人；装备部分是菜单，照主人的兴趣挑着装，不必全套照搬。
>
> 这是从一套真实运行中的个人助理配置里**抽象出来的通用骨架**：只讲方法与接入模式，示例均为品类与公开流程，不含任何一位具体用户的真实配置、账号、数据与凭据。密钥永远不进仓库——这是本包的第一条铁律，见 [07 号模块](modules/07-approvals-and-privacy.md)。

## 这套东西解决什么问题

个人助理用久了会长出四种病：

1. **接入靠临场发挥**——每接一个新服务都重新摸索，接完不留文档，下次全忘。
2. **巡检靠运气**——消息、邮件、日程散在各处，重要的漏看、不重要的反复提。
3. **记忆一锅粥**——什么都往一份记忆里塞，上下文越滚越贵，还互相打架。
4. **边界靠自觉**——什么能自己干、什么必须先批准，全凭当时的心情，容易出事。

本包把对应的章法固定下来，写成 Muse 能直接执行的文档。

## 先看总目录

[**CATALOG.md**](CATALOG.md) 是这份菜单的主菜页：验证过的连接器、API 和技能在里面逐条列明——是什么、怎么连、用户要去哪儿取 Key、接通后拿什么验证、有什么坑。逐条列全是为了方便筛选，不是要逐条装齐；新 Muse 接手时，先读总契约（SKILL.md），再按主人的兴趣和生活从目录里筛。另有一份 [OBSERVED.md](OBSERVED.md) 收录官方存在但**未验证**的生态清单，只供选型参考，不构成可用能力。

### 两条轨道，先选一条

- **轨道 A · 方法包**（[`modules/`](modules/) 九个模块）：讲怎么干活——巡检、记忆、边界、分工。想给自己的 Muse 立规矩的走这条，从 07（边界）和 03（记忆）开始。
- **轨道 B · 装备目录**（[CATALOG.md](CATALOG.md)）：讲能装什么——随仓技能包拷过去就能用，配方条目照步骤接。只想扩装备的走这条，不必先啃方法论；但动手装之前，先按下一节交一份菜单给主人挑。

**轨道之上还有一层：[SCENARIOS.md](SCENARIOS.md) 组合场景**——把几样装备焊在一起的配方卡（会前小抄、票务自动建历、睡眠门控晨报……）。单个能力都不稀奇，组合才是差距所在。它是菜单的套餐层：先看套餐想吃哪道，再回轨道 B 装下面的料。

### 先交一份装备菜单（读仓 Muse 的第一份交付）

读完本仓的 Muse，**第一份交付不是动手安装，而是给主人一份装备菜单，等主人勾选**。菜单不是把仓里的东西倒给主人看——先筛选、再端上桌。规矩四条：

1. 菜单交出之前不许装任何东西；主人没勾的，一律不碰。
2. **先筛后列**：结合你对主人的了解（生活习惯、兴趣、工作），把随仓技能包与 CATALOG 条目筛一遍——入选的进菜单正文；没入选的不要消失，在菜单末尾附一节「这次没端上来的」，每项一行（名字＋一句为什么这次不推荐），主人扫一眼能捞回来。筛选标准是「这个主人用得上吗」，不是「这东西好不好」。
3. OBSERVED 只提一句「还有一份未验证清单，需要时再看」，不进菜单。
4. 入选项每项四个要素缺一不可：**一句人话**（什么场景用得上，不许甩术语）＋**代价**（免 Key／要 Key 自取／付费）＋**一句风险**（只读还是能动手操作、碰不碰钱和账号）＋**你的推荐**（装／缓，必须给理由，结合主人的实际情况改写，不许照抄示例）。

## Muse 怎么采用（30 秒版）

1. 读根目录 [SKILL.md](SKILL.md)——这是总契约，读完就知道自己该怎么工作。
2. 按 [ADOPT.md](ADOPT.md) 的清单逐项落地：先边界（07），再记忆（03），再旁聊（04），然后按需接连接器（01）与巡检（02）。
3. 每落地一项，用真实查询验证一次再宣布完成——本包所有模块都遵守「没验证不算做完」。

### 直接复制这段话发给你的 Muse

把下面这段连同仓库链接一起发给你的 Muse，它就知道怎么采用本包（指令必须由你本人口头发出，它才会当作你的命令来执行）：

```text
读一下这个仓库：https://github.com/zhounuo528/muse-agent-playbook
先读 README.md，再读 SKILL.md（总契约）和 ADOPT.md（落地清单），细节按需看 modules/。

我要你把这套方法用在为我工作的日常里，顺序别乱：
0.5 先给我一份装备菜单（格式见 README「先交一份装备菜单」一节）：先按我的兴趣和生活习惯把随仓技能包与 CATALOG 条目筛一遍，入选的每项写清干嘛的、代价、风险和你的推荐，没入选的在末尾一行一个列清备查；OBSERVED 只提一句。我勾选之前，不许装任何东西，没勾的不许碰。
1. 先按 ADOPT 第 0 步跟我对齐边界——哪些对外动作必须先给我看确切内容、等我批准；
2. 再用 templates/ 落地记忆分层和旁聊分流，建我的核心记忆；
3. 连接器一家一家接，走 01 号模块的 SOP：我负责取 Key 和授权，你负责接入，并且用一次真实查询验证通过才算接通，接完把连接器文档和技能落档；
4. 巡检先跑一周影子模式，只分级、不打扰，校准好了再开主动提醒。

三个禁区：OBSERVED.md 全是未验证条目，不许当可用能力；一切密钥只走安全录入，不许让我在聊天里发明文；没验证过的事不许说做完。

读完先给我一句话总结＋装备菜单＋你的落地计划，我点头你再动手。
```

## 使用须知

- 本包是**方法纸**，不含任何可直接运行的凭据或针对具体账号的配置；接入任何服务都要走你自己的授权流程。
- 示例中的人物、公司、地名、金额均为虚构，仅用于说明结构。
- 平台规则会变，涉及具体服务的条款以官方文档为准。
