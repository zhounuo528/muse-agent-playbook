# 站点自动化运维【随仓附带】

用于第三方站点自动化在接入完成后的故障恢复与日常维护，包括登录态持久化、一键重建、站点改版后的选择器修复，以及对外效果的独立验证。

## 持久化登录态与一键重建

- 登录态（cookies、session 等）只放在持久化工作区的专属目录，绝不放在会被平台重置或清空的系统目录；登录态与构建产物分开存放。
- 登录态目录按凭据级别保护：目录权限 700、文件 600，不进代码仓库、不进云同步、不随备份外发；登录态失效或站点注销时当场删除旧文件；定期（如每季度）主动轮换一次，别等泄露了才换。cookies 等于半个账号密码，按凭据的规矩对待。
- 把安装依赖、构建、启动服务和只读健康检查写成一个放在持久化目录中的重建脚本，环境重置后运行一次即可恢复。
- 每次修好的故障都沉淀进重建脚本或修复日志，避免同一种故障靠临场记忆重复处理。

## 改版修选择器与独立验证

- 自动化突然报错时，先怀疑页面改版导致选择器过期：到站点确认新元素，新选择器优先、旧选择器留作兜底，修改后把原链路完整跑一遍回归。
- 自家通道的回读不算独立证据。对外可见的动作必须用第二账号、无登录状态或其他独立视角确认确实可见；确认前不要声称成功。
- 遇到验证码、输入控件无法写入等无法可靠自动化的阻断时，停止硬闯，转为人工处理或草稿交付。

## 通道选择

- 初次接入先完成端到端验收；本技能只负责接入后的持续运维。
- 有官方 API 或维护良好的官方工具时，优先使用官方通道，把网页自动化留作补充。
