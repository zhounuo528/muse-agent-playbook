# 08 · 睡眠门控

夜间不按固定钟点一刀切停工。用户睡没睡，用信号判；睡着就整轮静默，醒来的一瞬间把欠的活一次补齐。[02 号模块](02-heartbeat-inspection.md) 是巡检侧的简版口径，本模块是完整实现。

## 信号链（按优先级，上一级可用就不看下一级）

1. **睡眠状态文件（主信号）**：用户手机的快捷指令自动化在「睡眠专注」打开/关闭时，把一个小 JSON 写到云盘固定路径，巡检每轮先读它。
   ```json
   { "sleeping": true, "updated_at": "2026-11-09 02:26:29", "source": "iphone_sleep_focus" }
   ```
   - 新鲜度：`updated_at` 在约 16 小时内可用。`sleeping=true` 判在睡；`sleeping=false` 且时间明显晚于入睡时点，可能是唤醒跳变（见下）。
   - 已知失灵模式：关专注那次没写上 → 文件长时间停在 `true`。超过新鲜窗就判信号丢失，往下一级走，不要拿着过期文件整夜装睡。
2. **健康数据睡眠会话**：最近一段睡眠会话正在进行＝在睡；已结束且结束时间接近现在＝刚醒。
3. **时钟兜底**：前两级都拿不到时，用固定窗口（如 00:00–09:00）默认在睡。

**最高优先级覆盖**：用户在主聊天发了新消息，永远判醒——人在说话，不可能在睡。这一条压过所有信号，曾多次救下「专注状态滞后未翻转」的误判。

## 判睡着时

- 跳过统一轻巡检：不扫消息、不扫邮件、不比对日程、不更新水位；
- 跳过一切采样类动作；
- 不发任何消息（包括已授权的自动回复线——别半夜去 ping 真人的手机）；
- 只在水位文件里记一行判定依据。

## 判唤醒跳变时（上一状态睡着、本轮确认醒了）

立刻执行**唤醒包**：

1. **补扫整段睡眠窗口**：消息、邮件、日程从入睡水位起全量自检一遍——消息不丢，只是延后处理；
2. **晨报跟着唤醒走**：满足条件就立刻触发晨报，而不是死等固定时间：
   - 唤醒在清晨窗口内（如 05:00–12:00），且今天的「已提前发」标记未置位 → 触发，并置位标记，固定时间的晨报运行凭标记跳过，绝不重复发；
   - 固定时间运行时若发现用户还在睡，晨报**按住不发**并置「已按住」标记；此后当天 18:00 前出现唤醒跳变，补发；
   - 凌晨的短醒（起夜，多半会接着睡）不触发晨报，等下一次真正的唤醒跳变；
   - 同一天只触发一次。周期性简报（如周报）同理挂同一套标记逻辑。
3. 唤醒包不受常规静默窗限制（这是用户亲口定的起床仪式）；但醒后若无要紧事，只发一句简短早安汇总，不长篇。

判定结果只存一处（水位文件的门控区），不要多处各记一份互相打架。

## 代价（必须让用户知情并接受）

- 睡眠数据同步有延迟（几分钟到几十分钟），开关切换不是秒级；
- 睡眠中发生的安全/支付异常，要等唤醒包才被发现——夜间提前发现的机会是这套门控明码标价的代价；重要例外通道只适用于巡检实际运行的时段。
